# SERS public reporting app

This is a standalone, mobile-first public reporting website. Its HTML, styles,
and JavaScript live under `citizen-app/web`; it does not share the responder
dashboard's Next.js routes or components. It connects to the same Supabase
project using only the public publishable key.

## Run locally

From the repository root, create the ignored browser configuration and start a
static web server:

```bash
python3 citizen-app/scripts/setup_config.py
python3 -m http.server 4173 --directory citizen-app/web
```

Open <http://localhost:4173> in Chrome or Edge. Browser geolocation is requested
only after the user submits a report. Localhost is treated as a secure context
by modern browsers. To test on a phone, serve the app from an HTTPS host or an
HTTPS development tunnel; plain HTTP over a local network cannot use browser
geolocation on most phones.

`scripts/setup_config.py` reads the existing root `.env.local` (or deployment
environment variables) and writes the
publishable URL/key to `web/config.local.js`, which is ignored by Git. Never
put a Supabase service-role or secret key in this file.

## Supabase setup

Apply `supabase/migrations/20261115150000_public_reporting.sql` from the
repository root to the same
Supabase project used by the responder dashboard before submitting real
reports. It adds narrowly scoped public RPCs and private reporter, evidence,
and tracking-event tables. Submissions create incident and notification rows
in the existing dashboard tables so responders can receive them. The migration
does not change dashboard source files, existing table constraints, or Storage
permissions; anonymous users receive no direct table access.

The incident reference and a separate high-entropy tracking code are required
to read a report. The code is stored in the browser's local report list; keep
it private. The database stores only a hash of it. Reporter names, phone
numbers, evidence bytes, and tracking events remain in the non-exposed
`sers_private` schema.

No demonstration incidents are generated by this app. “My Reports” only lists
reports saved on the current browser/device. Clearing browser storage removes
that local list; the reference and tracking code can be entered again to track
the report.

## Browser smoke checks

With the local server running, run `node citizen-app/tests/browser-smoke.mjs`
from the repository root. It checks the navigation, mobile-width layout,
required-field validation, photo preview, denied-location behavior, and that a
failed database response never shows a success screen. The database errors in
this smoke check are simulated; it does not create an incident in Supabase.

## Project layout

- `web/` contains the deployable public website.
- `web/js/` contains reporting, location and tracking modules.
- `scripts/` contains local and deployment setup utilities.
- `tests/` contains browser smoke checks.
- The shared database migration stays in the repository's root
  `supabase/migrations/` folder because it changes both the citizen app and
  responder dashboard data contract.
